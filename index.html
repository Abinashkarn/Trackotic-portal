Rules that apply everywhere

Two QR types only: DEVICE QR (/d/<token>, permanent) and PASSPORT QR (/p/<token>, one per unit / carton / tube / pouch — one name for every vertical, only the label size differs).
Scanning any device QR does one thing: bind passport QRs to it. Same page for HUB, PRO, LITE, LOCKBOX.
A passport is on ONE device at a time; a new bind releases the previous binding and closes that leg. Passports never close; VOID is the only exit.
Chain is dynamic (2…n legs). Journey templates are expectation, never enforcement. Carton legs are inherited by the units inside.
Visibility: staff see all · tenant sees own legs + the one received from · patient sees the whole chain anonymised with the last leg in detail · bank environments have no public route.
Patient scan opens the compliance PDF inline. Six states: COMPLIANT · NOT COMPLIANT step N · COMPLIANT WHERE MONITORED · JOURNEY IN PROGRESS · NOT YET IN A JOURNEY.
Track0tic mints every passport QR. QR labels is one screen: tenant → print device QRs (= allocation) → generate passport QRs → Track0tic prints & couriers, or tenant prints.
Tenant creation is company-first; the tenant page demands the first tenant admin before anything can be allocated. "Hosted on": Shared platform / Muthoot · dedicated / Axis Bank · dedicated.
On any screen with a picker, everything below it follows the pick and the primary button names what it will act on.

STEP 1 · DEVICES IN (Track0tic admin) — register supplier → receive → QC (SIM bound, TRK ID) → QR labels: the label is printed at the moment the device is allocated to a tenant.

A0desktop
Staff sign-in
Staff only (Track0tic employees). Email + password; 2FA step shown but repo has none yet (phase 2). 5 failures → 15 min lock. Tenant users never log in here.
A0adesktop
Register device supplier / manufacturer
WHY: a device can only be received against a registered supplier + approved model. Keeps warranty/RMA, drives QC sampling by fail rate. Supplier is a record, NOT a tenant — no login. Warranty 12/18/24/36 m.
A1desktop
Receive devices
Creates devices as inactive · unlabelled. Serials pasted or CSV, or arrive by "hello" message from an allowed factory. No TRK ID yet. Partial receipt allowed. Batch id RB-####.
A2desktop
QC & firmware → TRK ID
Bench check per device: power, telemetry seen, firmware = target, probe ±0.3 °C, enclosure, battery. SIM BOUND recorded here (ICCID + M2M whitelist). PASS assigns TRK ID + queues label. FAIL → RMA to supplier.
A3desktop
QR labels — tenant → print device QRs (= allocate) → generate passport QRs (print here / tenant prints / courier)
THE ONE QR SCREEN (decided 29 Oct): 1 pick tenant → 2 device type + quantity → Print device QRs = allocation to that tenant (labels permanent, 60×30, /d/<token>) → 3 passport QR quantity + size + cartons + who prints → Generate book. Track0tic prints & couriers, or tenant prints from T1. Tenant top-up requests load into step 3. PDF default; ZPL = raw thermal-label-printer format, optional.
A4desktop
Inventory
Stages: awaiting QC → SIM bound → QC pass/unlabelled → in stock → allocated → maintenance/revoked. Click a stage card = filter. Bulk: allocate, print, maintenance, revoke.
A4adesktop
Device detail
One device: live temp, battery, drift (live rows only), passports on it (all legs — admin sees everything), identity, device_events timeline. Revoke = dead link on scan.

T1desktop
Tenant portal — passport stock & print
Tenant portal. Books issued to this tenant; print at 100 %, PRINT is an audit event (who/when/which codes). Request more → Approvals. Cannot mint.
D3PDF/print

ONE label type for everything that moves: PASSPORT QR — standard 40×25, tube size 25×12, carton flag. Device QR 60×30 (HUB 80×40). QR encodes full URL never bare id; 8-char short code under every passport QR.

Camera + typed 8-char code ALWAYS both. Each bind saved instantly. Carton = all inside. ONE DEVICE AT A TIME: a new bind releases the previous binding and closes that leg. Typed binds tagged TYPED.

Passport QR scanned by custodian/staff: journey newest first — own legs + the one received from (grants widen). Hand over / Bind. Custodian PDF (D2).

Part of a carton stays: units that leave KEEP every step travelled inside the carton, then start their own leg; carton continues with the rest. Nothing reprinted. Scanning one unit's own QR = same.

No signal: last code kept on screen, NEVER auto-retried (no double binds). Earlier binds already saved server-side.
F1phone

Logged in, device belongs to another tenant → bind to your own device instead. Server returns 403 with tenant name hidden.
F2phone

Unknown token / mistyped code. Same page for a non-existent passport. On bank environments this page = ALL unauthorised scans (never confirm existence).

STEP 4 · PATIENT (public, no login) — scan passport → compliance PDF opens: whole chain anonymised, last leg in detail. D2 is what the custodian gets instead.

6phone
Patient scans → compliance PDF (phone)
Patient scans → PDF opens INLINE (Content-Disposition inline), no landing page. Whole chain anonymised, last leg detailed. No names/places/TRK IDs. Bank environments: 404.
D1PDF/print
Compliance report — public PDF · 6 states in props: retail-only / full-8 / gaps-only / gap+breach / journey-in-progress / not-yet-bound
6 STATES in props: COMPLIANT · NOT COMPLIANT step N · COMPLIANT WHERE MONITORED (no device or missing readings) · JOURNEY IN PROGRESS (open leg, snapshot + generation time) · NOT YET IN A JOURNEY (never bound). Cached per closed leg; in-progress generated live.
D2PDF/print
Compliance report — custodian copy
Custodian copy: names, places, device ids for OWN legs + adjacent handovers. Legs close on device time (last_recorded_at), never phone clock. Not for public distribution.

Decisions & backlog

Rules carried from the spec: public pages never show location, tenant names or TRK ids. Passport never closes. Typed binds are tagged. Track0tic issues every passport. 28 Oct: the public scan opens the compliance PDF for the WHOLE chain (anonymised — Storage/Transit steps), last leg in detail. DECIDED 28 Oct: a passport is on ONE device at a time — a new bind releases the previous binding automatically (that leg closes). Any missing readings or missing device → verdict "COMPLIANT WHERE MONITORED" (D1 chain "with-gap-and-breach" shows both kinds of gap).
Chain is dynamic: could be 2 steps (retail HUB → Pro → patient) or 8 (manufacturer HUB → Pro → CFA HUB → Pro → distributor HUB → Pro → retail HUB → Pro). Carton legs at the manufacturer are inherited by every unit inside. Verdict: COMPLIANT · NOT COMPLIANT at step N · COMPLIANT WHERE MONITORED (gap).
Hindi: every field string exists in Hindi too (design system rule). Same layout, same sizes; the toggle sits in the app bar. Not drawn twice here — copy sheet to follow from the content team.
PHASE 2 (not drawn): (e) device return / de-allocation page (today only via Approvals); (f) reference data admin page (sales categories, states, locations). DONE 29 Oct: journey-in-progress + not-yet-bound PDF states (D1), carton split (F5a), issuer alert SMS + profile switch.
BRAND (28 Oct): wordmark is Track0tic™ everywhere — the 0 is a zero in red (#e11d2e; #ff5a66 on dark), never the letter O, never blue; ™ superscript always follows. Applies to app bars, admin sidebar, PDFs, labels, SMS sender name text.
